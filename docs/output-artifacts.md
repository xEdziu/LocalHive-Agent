# Output Artifacts

Output artifacts are files produced by a Docker workload inside the container and uploaded by the Agent to the Master after the container exits.

Examples:

- `/output/result.txt`
- `/output/results/output.json`
- `/output/logs/summary.txt`

## Current Agent Flow

1. Agent creates an execution-scoped local output directory.
2. Agent mounts that directory into Docker as writable `/output`.
3. Docker workload writes result files into `/output`.
4. After the container exits, Agent scans the output directory.
5. Agent uploads regular files to the Master as `EXECUTION_OUTPUT` artifacts.
6. Agent uploads output artifacts before reporting the terminal execution result.
7. If `/output` is empty, nothing is uploaded.

## Local Layout

```text
.localhive-agent/outputs/<executionId>/
`-- output/
    `-- ...
```

The host path is generated by the Agent. Workload configuration cannot choose the host output path.

There is no cleanup or retention policy yet. Output directories may remain on disk for debugging until they are removed manually or a future cleanup feature is added.

## Docker Mount

Docker workloads receive the output directory as a writable bind mount:

```text
--mount type=bind,source=<outputDir>,target=/output
```

Rules:

- `/output` is writable.
- `/workspace` remains read-only when workspace artifacts are used.
- only the Agent-generated output directory is writable.
- user-defined output mount paths are not supported.

## Output Scanner

After Docker exits, the Agent scans the execution output directory.

Scanner behavior:

- recursive scan
- regular files only
- empty directories ignored
- deterministic ordering
- relative paths normalized to `/`
- symlinks rejected
- invalid file types rejected
- path traversal rejected
- path escape after normalization rejected

## Limits

| Limit | Current value |
| --- | --- |
| Maximum output files | 100 |
| Maximum single output file size | 50 MiB |
| Maximum total output size | 200 MiB |
| Maximum relative path length | 1024 |

## Upload Behavior

Agent uploads each output file to the Master endpoint:

```http
POST /api/workers/{workerId}/executions/{executionId}/artifacts/output
```

Headers:

```text
X-API-KEY
X-EXECUTION-LEASE
```

Request:

- multipart field `file`
- multipart field `relativePath`

The upload is streamed and happens while the execution is still `RUNNING`. The terminal execution result is reported only after output upload finishes.

API keys and execution lease tokens must not be logged. File contents are not stored in local task history.

## Failure Behavior

Docker succeeds and output upload succeeds:

- execution reports `SUCCEEDED`

Docker succeeds and output upload fails:

- execution reports `FAILED` with `OUTPUT_ARTIFACT_UPLOAD_FAILED`

Docker fails and output upload succeeds:

- execution reports `FAILED` with the original Docker failure code

Docker fails and output upload also fails:

- execution reports `FAILED` with the original Docker failure code
- output upload failure is secondary

Docker timeout:

- output upload is skipped in A5 V1
- execution reports Docker timeout failure

## Failure Codes

| Code | Meaning |
| --- | --- |
| `OUTPUT_DIRECTORY_PREPARATION_FAILED` | Agent could not prepare the local output directory. |
| `OUTPUT_DIRECTORY_INVALID` | Agent detected unsafe output files, symlinks, path traversal, invalid file types, or exceeded output limits. |
| `OUTPUT_ARTIFACT_UPLOAD_FAILED` | Docker succeeded, but Agent could not upload output artifacts to the Master. |

## Security Notes

- There is no user-controlled host output path.
- Only the Agent-generated `/output` bind mount is writable.
- Workspace mount remains read-only.
- Scanner does not follow symlinks.
- Output relative paths are metadata only on the Master.
- API key and lease token are not logged.
- Output contents are not stored in local SQLite history.
- Docker still runs with `--network none`.
- Privileged mode is not used.
- Host network is not used.
- `docker.sock` is not mounted.
- GPU flags are not used in the current implementation.

## Current Limitations

- no cleanup or retention policy yet
- no output UI in Agent yet
- no output preview
- no large multi-GB output artifacts
- no writable workspace
- no distributed or sharded output aggregation
- timeout outputs are skipped in A5 V1

## Future Extensions

Future work may add:

- cleanup or retention policy
- Agent UI refresh for current execution and output upload status
- output upload progress
- output artifact counts in local history
- large artifact policy
- Minecraft or Fabric server logs, backups, and snapshots
